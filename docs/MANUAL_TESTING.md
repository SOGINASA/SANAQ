# Ручное тестирование SANAQ

Документ описывает воспроизводимый маршрут проверки приложения человеком: от нового
аккаунта ученика до кабинетов учителя и администратора.

## 1. Подготовка стенда

### Backend

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m flask --app app seed-demo
python app.py
```

Seed идемпотентный: повторный запуск обновляет демо-набор и не создаёт дубликаты.
Backend доступен на `http://127.0.0.1:8000`.

Seed содержит 18 учебных заданий: по три варианта на каждый навык. Одна диагностика
по-прежнему состоит из шести вопросов, но для нового прохождения варианты могут отличаться.
Внутри уже начатой диагностики набор фиксирован, поэтому обновление страницы не заменяет вопрос.

### Frontend

В отдельном терминале:

```powershell
cd frontend
npm install
Copy-Item .env.example .env
npm start
```

Открыть `http://localhost:3000`. В `.env` должно быть:

```dotenv
REACT_APP_API_URL=http://127.0.0.1:8000/api/v1
REACT_APP_AI_STREAM_URL=http://127.0.0.1:8000/api/v1
REACT_APP_ENABLE_MOCKS=false
REACT_APP_SHOW_DEMO_LOGIN=true
```

## 3. Сквозной путь нового ученика

Для действительно чистого прогона лучше каждый раз регистрировать новый email, например
`human.test+01@example.com`. Так не нужно очищать базу после завершённой диагностики.

1. На `/register` создать аккаунт ученика и войти.
2. Убедиться, что приложение направляет на onboarding, а закрытые страницы без входа
   возвращают на `/login`.
3. Выбрать 9 класс, математику и учебную цель; сохранить профиль.
4. Пройти диагностику полностью. Специально дать и правильные, и неправильные ответы.
5. Проверить результат: процент, сильные стороны и пробелы должны соответствовать ответам.
6. Дождаться генерации маршрута и открыть `/student/path`.
7. Открыть первый доступный урок, начать задание, сначала дать неверный ответ, запросить
   подсказку/объяснение, затем дать правильный ответ и завершить попытку.
8. Проверить `/student/progress` и `/student/knowledge-map`: изменённый навык и попытка
   должны отразиться без перезагрузки данных вручную.
9. Открыть `/student/assistant`, создать диалог и задать вопрос по текущей теме. Если AI
   недоступен, интерфейс должен явно показать безопасный fallback, а не пустой успех.
10. В `/student/settings` ввести код `SANAQ9A`, затем открыть `/student/class`.
11. Проверить закреплённое объявление и опубликованное назначение. Черновик учителя ученик
    видеть не должен.
12. Открыть колокольчик, перейти по уведомлению и отметить уведомления прочитанными.
13. Проверить смену языка RU/KK/EN, крупный текст, контраст, уменьшение анимации и
    озвучивание задания.
14. Выйти; обновление страницы не должно возвращать в защищённый кабинет.

## 4. Путь демо-ученика

Войти как `student@sanaq.demo`. Этот аккаунт уже находится в классе, поэтому удобен для
быстрой проверки объявления, назначения и уведомления до прохождения диагностики. После
одного полного прогона его состояние сохраняется; для повторной проверки «с нуля» нужно
использовать новый зарегистрированный email.

## 5. Путь учителя

1. Войти как `teacher@sanaq.demo` и открыть dashboard.
2. В классе `9A · Демо` проверить четыре строки учеников и три состояния: стабильный,
   требует внимания, риск. Среднее значение и heatmap не должны быть пустыми.
3. Открыть профили Алины, Данияра и Арсена; сравнить mastery и слабый навык.
4. У Данияра проверить сохранённый комментарий. Добавить новый комментарий с опцией
   добавления в план, затем войти учеником и проверить уведомление.
5. На странице назначений открыть опубликованное назначение: Алина должна иметь 100%,
   Данияр — 50%, остальные — 0%. Черновик не должен быть виден ученикам.
6. Во вкладке «Аналитика» раскрыть карточку в «Живой карте ошибок». Проверить условие
   предложенного микро-задания и список затронутых учеников. Нажать «Назначить
   микро-задание», установить срок и подтвердить. Назначение должны получить только
   перечисленные в карточке ученики; остальные ученики класса не должны видеть его в ленте.
   Повторить сценарий через режим «Своё задание»: заполнить условие, правильный ответ,
   подсказку и объяснение. После назначения открыть аккаунт затронутого ученика, решить
   созданную задачу сначала неверно, затем верно; незатронутый ученик её видеть не должен.
7. Создать новое назначение, опубликовать его и проверить его появление в классе ученика.
8. Создать закреплённое объявление, проверить уведомление ученика, затем удалить объявление.
9. Создать класс, скопировать код и присоединить к нему новый ученический аккаунт.
10. В библиотеке контента создать модуль, урок и задания разных типов; проверить preview,
   autosave, публикацию и появление материала в каталоге.

## 6. Путь администратора

1. Войти как `admin@sanaq.demo`; на dashboard должны быть пользователи, класс, модули,
   открытая жалоба на AI и запись аудита.
2. В пользователях проверить поиск и фильтр ролей; создать временного пользователя,
   сменить роль/пароль, заблокировать и восстановить доступ.
3. В классах открыть `9A · Демо`, изменить название и вернуть его обратно. Удаление
   проверять только на отдельно созданном временном классе.
4. В модерации открыть seed-жалобу на AI, перевести её в `reviewing`, затем закрыть с
   резолюцией. Проверить появление действий в журнале аудита.
5. В разделе системы проверить backend, БД, AI и планировщик. Недоступный AI должен иметь
   отдельный degraded/error статус и не ломать остальные сервисы.
6. Проверить доступ по ролям: admin не должен попадать в student/teacher routes, учитель —
   в admin routes, ученик — в teacher routes.

## 7. Критерии успешного прогона

- нет необъяснимых пустых экранов и бесконечных loading-состояний;
- после мутаций данные сохраняются после перезагрузки страницы;
- опубликованное появляется у нужной роли, черновики и скрытые ответы не утекaют;
- ошибки API показываются понятным сообщением и позволяют повторить запрос;
- мобильная ширина 360 px не создаёт горизонтальный скролл;
- все действия доступны клавиатурой, виден focus, диалоги удерживают фокус;
- RU, KK и EN не смешиваются на одном экране, кроме пользовательского контента;
- выход, истечение access token и refresh-сценарий не оставляют защищённые данные на экране.

## 8. Что проверять после каждого изменения логики

Минимальная регрессия: регистрация → onboarding → диагностика → маршрут → попытка →
прогресс; затем публикация назначения учителем → появление у ученика → контроль доступа
администратором. Перед ручным прогоном выполнить:

```powershell
cd backend
python -m pytest -q

cd ..\frontend
npm test -- --watchAll=false
npm run build
```
