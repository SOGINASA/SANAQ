# Kaspi в hackathon demo SANAQ

## Что делает текущий MVP

Это не интеграция Kaspi Pay и не настоящий платёж. Все три тарифа показывают символическую
цену 1 ₸, но банковская операция не создаётся и деньги не списываются.

Пользовательский сценарий:

1. Ученик выбирает тариф на `/student/billing`.
2. Backend создаёт ожидающую demo-запись `Payment`.
3. Frontend сохраняет ID этой записи в текущей вкладке и пытается открыть обычное приложение
   через `kaspi://`. Если браузер не поддержал схему, открывается `https://kaspi.kz/`.
4. Пользователь возвращается в SANAQ кнопкой «Назад» или переключением приложения.
5. SANAQ автоматически показывает пятисекундную анимацию обработки.
6. Backend переводит demo-запись в `paid` и активирует тестовую подписку на 30 дней.
7. На welcome-экране явно указано, что реально списано `0 ₸`.

Номер телефона, реквизиты, сумма и назначение платежа в Kaspi не передаются.

## Конфигурация хоста

В `.env` backend достаточно оставить провайдера для внутренней маркировки записей:

```dotenv
PAYMENT_PROVIDER=kaspi
```

После изменения переменных перезапустите backend:

```bash
docker compose up -d --build backend
```

Demo-режим зафиксирован в платёжном сервисе MVP, поэтому merchant-ссылка и дополнительные
переменные Kaspi для запуска не нужны.

## Важные границы

- Экран SANAQ не копирует интерфейс Kaspi и помечен как `DEMO`.
- Статус `paid` в этом режиме означает только успешное завершение демонстрации.
- Записи этого режима нельзя использовать для бухгалтерского учёта или подтверждения оплаты.
- Для настоящего запуска понадобится официальный договор, документированный provider flow и
  серверная проверка статуса. Возврат пользователя в браузер сам по себе никогда не является
  доказательством реального платежа.
